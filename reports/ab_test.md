# A/B-тест кредитной политики (симуляция на test)

Группа A — бейзлайн (логистическая регрессия на сырых признаках), группа B — LightGBM. В каждой группе одобряется 70% заявок с наименьшим PD. Метрика — доля дефолтов среди одобренных (bad rate). Гипотеза H0: bad rate одинаков. Тест — двусторонний z-тест для двух долей, α = 0.05.

## Один эксперимент

A: 260 дефолтов из 2096 одобренных (0.124); B: 264 из 2104 (0.125); z = 0.14, p = 0.8885. Один тест такого размера легко не показывает эффект — см. мощность ниже.

## 2000 случайных разбиений

| | A/B (старая vs новая) | A/A (старая vs старая) |
|---|---|---|
| средний bad rate A | 0.1284 | 0.1286 |
| средний bad rate B | 0.1154 | 0.1282 |
| доля экспериментов с p < 0.05 | **24.2%** (мощность) | **5.1%** (ошибка I рода) |

## Размер выборки

Истинный эффект на всём test: bad rate 0.1288 → 0.1152 (−11% относительно). Для мощности 80% нужно ≈ **9,130** одобренных клиентов в каждой группе, у нас ≈ 2,100. Отсюда мощность меньше 80%.

## Что важно в реальном тесте

- Метка дефолта созревает месяцами: в реальном тесте bad rate измеряют через 3–12 месяцев после выдачи.
- Отказанных клиентов не видно (reject inference): сравнивать модели на исторических одобренных — смещённо, A/B с рандомизацией это смещение убирает.
- Guardrail-метрики: доля одобрений, средний лимит, прибыль, доля одобрений по сегментам (без дискриминации).
- Рандомизировать надо по клиенту, а не по заявке: повторные заявки одного человека не должны попасть в разные группы.
